# Core product scope

## Core outcome

A developer can open ATLAS, understand their current workspace, find and open a project, launch installed tools, use the initial AI workspace under clear permissions and manage essential preferences.

## Core capability groups

- App shell, onboarding and dashboard.
- Project registration, organisation and project detail.
- Application launcher and developer tool detection.
- AI workspace with Helper/Tutor, Developer and Hybrid modes.
- Model/provider configuration with clear local/cloud distinction.
- Git overview and safe local repository actions.
- Basic system and hardware information.
- Local settings and secret protection.
- AAP and Permission Manager foundation.
- Core voice essentials only if validated as feasible for the milestone.
- Activity feedback for important actions.

See [CORE_VS_PRO.md](../CORE_VS_PRO.md) and the individual [Core feature specifications](../Features/Core/).

## Acceptance approach

Core is not complete because a screen exists in Figma. Each capability needs an implementation, an explicit acceptance criterion, platform testing and a documented limitation where necessary.

## Scope control

When schedule pressure appears, reduce or defer lower-priority breadth rather than weaken security, privacy, permission boundaries, installation safety or basic reliability. Keep a visible list of deferred work.
