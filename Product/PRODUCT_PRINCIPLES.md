# Product principles and audience

## Intended audience

Developers who work across multiple repositories, tools and environments and want a consistent starting point for daily work. The initial design should be approachable to learners while remaining efficient for experienced developers.

## Product principles

1. **Daily utility:** reduce the friction between opening the computer and starting meaningful development work.
2. **Complements, does not replace:** launch and coordinate specialist tools rather than rebuilding every tool inside ATLAS.
3. **Local-first:** core workspace functions should not depend on an ATLAS-hosted account.
4. **Privacy-conscious:** explain external data sharing and keep secrets protected.
5. **User agency:** installation, destructive changes, remote actions and sensitive operations remain under user control.
6. **Predictability:** show what an action will do and what happened afterward.
7. **Progressive disclosure:** keep common tasks easy to find without overwhelming new users with every advanced setting.
8. **Cross-platform honesty:** support Windows and Linux through actual testing, not assumptions.
9. **Useful before clever:** favour dependable workflows over novelty or feature count.

## Non-goals

- Replacing every IDE, terminal, Git host or operating-system settings application.
- Running AI agents with unrestricted access.
- Requiring a cloud account for ordinary local workspace use.
- Automatically installing tools without user consent.
- Presenting speculative hardware or compatibility estimates as facts.
- Optimising a single process metric while ignoring total application resource use.
